1.Propósito, alcance y adaptación

Este plan define cómo se inicia, planifica, controla, ejecuta y evidencia el aseguramiento de calidad de CodePortfolio. Cubre la SPA React, la API ASP.NET Core, PostgreSQL, el almacenamiento de imágenes, la configuración de contenedores y los documentos del producto.

Declaración de conformidadEl documento está adaptado a IEEE 730-2026 para un proyecto académico de una sola persona. No declara certificación ni conformidad total: esta requiere aplicar el plan, conservar evidencias, resolver hallazgos y obtener aprobaciones independientes cuando corresponda.

4.1 Normas y prácticas aplicables

  • Requisitos: identificador único, lenguaje inequívoco, prioridad, fuente, estado, criterio verificable y trazabilidad bidireccional.
  • Código: revisión antes de integrar; secretos fuera del repositorio; validación de entradas; autorización por recurso; migraciones versionadas.
  • Configuración: cada liberación debe vincular versión, commit, migraciones, imágenes, variables documentadas y resultado de pruebas.
  • Pruebas: evidencia reproducible con fecha, versión, entorno, datos, ejecutor, resultado y defecto asociado.
  • Documentación: versión, responsable, aprobación, referencias, historial y estado; los valores por completar no se presentan como hechos.

5.Gestión de defectos y acciones correctivas

  1. Registrar el hallazgo con identificador, versión, entorno, pasos, evidencia, resultado esperado/real y severidad.
  2. Triage por producto, desarrollo y calidad: aceptar, duplicar, diferir o asignar.
  3. Corregir en una rama/cambio trazable y añadir o actualizar una prueba de regresión.
  4. Verificar la corrección en el mismo entorno y revisar impactos laterales.
  5. Cerrar únicamente con evidencia. Un defecto diferido exige riesgo aceptado, responsable y fecha objetivo.

Conclusión de calidadLa documentación inicial era una base útil, pero el PDF consolidado no reemplazaba un SQAP ejecutable. Esta versión incorpora métricas, puertas, auditorías, control de configuración, defectos, registros y un diagnóstico verificable. El producto no está autorizado para producción hasta cerrar los elementos marcados como bloqueantes.

8.Aceptación y mantenimiento del plan

El plan se revisa ante cambios de alcance, arquitectura, riesgos, proceso o estándar, y al menos en cada liberación. Las excepciones deben identificar control omitido, causa, riesgo, compensación, responsable, vencimiento y aprobación. La firma de este documento aprueba el proceso; no sustituye la evidencia de que se ejecutó.
