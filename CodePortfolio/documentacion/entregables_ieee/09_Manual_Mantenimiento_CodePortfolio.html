1.Propósito

Mantener CodePortfolio estable, seguro y recuperable. La topología considerada es PostgreSQL 16, API ASP.NET Core 8, frontend Nginx/React y volúmenes Docker.

2.Tipos de mantenimiento

TipoEjemplo
PreventivoRevisar espacio, logs, actualizaciones y restauraciones.
CorrectivoResolver una falla de autorización o despliegue.
EvolutivoIncorporar mensajería o panel administrativo visual.
AdaptativoActualizar imágenes base, TLS o configuración de navegador.

3.Cronograma preventivo

ActividadFrecuenciaResponsable
Revisar servicios, CPU, RAM y volúmenesSemanalOperación
Revisar logs de API y baseSemanalDesarrollo
Respaldar DB e imágenesDiario / RPO aprobadoOperación
Revisar vulnerabilidades de paquetes e imágenesMensual y antes de liberarDesarrollo
Probar restauración completaTrimestral y antes de cambios críticosDBA / Calidad
Ejecutar regresiónCada cambio materialDesarrollo / Calidad

4.Incidentes correctivos

  1. Registrar fecha, síntoma, impacto, versión y evidencia sin secretos.
  2. Clasificar gravedad: crítica, alta, media o baja.
  3. Contener la falla y preservar evidencia.
  4. Reproducir de forma segura en pruebas.
  5. Corregir, ejecutar regresión y solicitar revisión.
  6. Desplegar, observar y documentar la causa raíz antes de cerrar.

5.Diagnóstico y respaldo

SituaciónComando
Estadodocker compose ps
Logs APIdocker compose logs -f backend
Logs DBdocker compose logs -f db
Recursosdocker stats
Respaldo lógicodocker compose exec -T db pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > codeportfolio_YYYYMMDD.sql
RestauraciónIncluye siempre la base de datos y el volumen de imágenes. Restaura primero en un ambiente aislado; nunca sobrescribas producción sin aprobación y punto de recuperación.

6.Despliegue y contingencia

EventoAcción inicial
LiberaciónIdentificar commit/artefacto, confirmar respaldo y ejecutar pruebas de humo.
API caídaRevisar estado y logs; comprobar conexión a DB antes de reiniciar.
DB no saludableEvitar escrituras, revisar disco/logs/credenciales y recuperar de forma aislada si hace falta.
Fuga posibleRotar secretos, revocar sesiones, preservar evidencia y evaluar alcance.
Acceso indebidoRevocar sesiones, corregir autorización y ejecutar regresión actor-recurso.
